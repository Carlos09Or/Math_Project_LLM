Glosario

Los términos técnicos del proyecto, en lenguaje llano. Si encuentras uno que no está aquí, es un hueco del glosario, no tuyo.


Modelos y compresión

Modelo de lenguaje pequeño (SLM)
Un modelo de lenguaje con pocos miles de millones de parámetros o menos (aquí, de 0,6 a 3,8 mil millones), lo bastante ligero para correr en un portátil o, a futuro, en un teléfono.
Parámetros
Los números que el modelo aprendió y que guardan su «conocimiento». Más parámetros suele significar más capacidad, pero también más memoria y más lentitud.
Cuantización
Guardar esos números con menos precisión para que el modelo ocupe menos memoria y corra más rápido, a costa de perder algo de calidad. Es como comprimir una foto: pesa menos, pero puede perder detalle.
FP16, Q8_0, Q4_K_M
Tres niveles de precisión del mismo modelo. FP16 es el original (16 bits por número), Q8_0 usa unos 8 bits y Q4_K_M unos 4. Cuanto menor el número, más pequeño el archivo. Por eso comparamos las tres versiones de un mismo modelo: es lo único que cambia.
Ollama
El programa que ejecuta los modelos en el equipo, sin internet, y reporta tiempos y cantidad de tokens.
Digest
Una huella única del archivo exacto de un modelo. Garantiza que dos corridas usaron literalmente el mismo modelo.
Modo «thinking»
Algunos modelos «razonan en voz alta» antes de responder. Se fija igual en todas las corridas para que no sea una variable oculta.

Equipo y costo

GPU y VRAM
La tarjeta gráfica y su memoria. El laboratorio tiene una RTX 3060 Laptop de 6 GB de VRAM. Si un modelo no cabe completo en la VRAM, parte se ejecuta en el procesador y todo se vuelve más lento.
Offload (GPU pura o híbrida)
Indica si el modelo corre entero en la GPU («GPU pura») o repartido con la CPU («híbrido»). No se mezclan ambos modos en una misma comparación de velocidad.
Token y tok/s
Un token es un trozo de texto (más o menos una sílaba o palabra corta). «Tokens por segundo» mide qué tan rápido escribe el modelo.
TTFT
Tiempo hasta el primer token: cuánto tarda el modelo en empezar a responder. La medición con instrumentación propia es una fase posterior (F4).
Reportado, medido y derivado
Un dato reportado lo informa Ollama; uno medido lo mide una herramienta externa (por ejemplo nvidia-smi); uno derivado se calcula a partir de los anteriores. El sitio los rotula por separado y no inventa los que faltan.

Evaluación y estadística

Benchmark
Un conjunto fijo de problemas con respuestas conocidas, que sirve para comparar modelos en igualdad de condiciones.
Ítem, problema base y familia
Un ítem es una pregunta concreta. Varios ítems pueden salir del mismo problema base (o familia), por ejemplo resolverlo, diagnosticar un error y dar una pista. Como no son independientes entre sí, la estadística los agrupa.
Las tres tareas
Resolver: dar la respuesta correcta. Diagnosticar: reconocer el error de un estudiante, o que no hay error. Pista: orientar sin revelar la respuesta.
Control
Un caso donde el trabajo del estudiante es correcto. Sirve para saber si el modelo inventa errores donde no los hay.
Corrector determinista
Un programa que puntúa con reglas fijas (¿la respuesta es exacta?, ¿el veredicto es correcto?, ¿la pista contiene el resultado?). Da siempre el mismo resultado y no depende de la opinión de otro modelo.
Veredicto y categoría
En el diagnóstico, el veredicto es decir si el trabajo está bien o mal; la categoría es el tipo de error que el modelo dice haber encontrado.
Fuga (de la pista)
Una pista que contiene la respuesta final. Una pista con fuga no cumple su función. Ojo: que no haya fuga no significa que la pista sea buena.
Intervalo de confianza (IC 95 %)
El rango en el que probablemente está el valor «real» si repitiéramos la prueba con otros problemas parecidos. Si los intervalos de dos modelos se solapan, no se puede afirmar que uno sea mejor que el otro.
Bootstrap por problema base
Una manera de calcular intervalos volviendo a muestrear familias de problemas, no ítems sueltos, para no exagerar la certeza.
Ablación
Cambiar una sola cosa a propósito para ver qué la explica. Aquí: darle al modelo la respuesta correcta, o pedirle que resuelva primero, para entender por qué no detecta el error.
Ronda y temperatura
Una ronda es una pasada completa por todos los ítems. La temperatura controla cuánto azar usa el modelo al escribir: con 0 casi siempre responde igual; con valores más altos varía.
Exploratorio y confirmatorio
Un resultado exploratorio sugiere una pista y genera preguntas; uno confirmatorio se diseñó de antemano para comprobar una hipótesis con muestra suficiente. Todo lo publicado hasta ahora es exploratorio.
Frontera de Pareto
El conjunto de configuraciones que no se pueden mejorar en calidad sin empeorar el costo (o al revés). Sirve para elegir según lo que importe más.

Datos y reproducibilidad

Prompt congelado
La instrucción que se le da al modelo, fijada de antemano y protegida con una huella (SHA-256) para que no cambie entre comparaciones.
SHA-256
Una huella digital de un archivo. Si cambia una sola letra, la huella cambia. Permite comprobar que los datos no se alteraron.
Benchmark congelado
Ítems, reglas y configuración quedan registrados con su huella antes de evaluar; el motor se niega a correr si algo cambió.
Manifiesto
El «acta» de una corrida: fecha, versiones, hardware, modelo y digest, huella de los datos y configuración usada.
Particiones dev y pilot
dev se usa para ajustar el prompt; pilot se reserva para evaluar. Separarlas evita «hacer trampa» ajustando sobre lo que luego se mide.
Contaminación
Que los ítems de evaluación terminen en los datos con los que se entrenan los modelos, lo que inflaría los resultados. Por eso los 180 ítems no se publican.

Currículo y revisión humana

MEDUCA y competencia
El Ministerio de Educación de Panamá. Una competencia es una capacidad concreta que el programa espera que el estudiante logre (por ejemplo, restar con reagrupación). Cada ítem cita la suya y su página.
Programa 2024 y programa 2026
Dos ediciones del programa de tercer grado. El dataset de 2024 usa la primera y el benchmark 2026, la segunda (en fase de validación). Ninguna tiene todavía aval docente en este proyecto.
Oficial y metodológico
Un límite oficial sale del programa, con página. Uno metodológico es una decisión del equipo (por ejemplo, excluir el cero) y no se presenta como exigencia de MEDUCA.
Rúbrica y ejemplos ancla
Una escala de 0 a 2 con descripciones de cada nivel. Los ejemplos ancla son respuestas reales que ilustran cada puntaje para que distintas personas califiquen igual.
Revisión ciega y doble anotación
Calificar sin saber qué modelo respondió, y que dos personas califiquen una muestra por separado para medir cuánto coinciden.
MathTutorBench
Un benchmark público de tutoría matemática. Se estudia su metodología para adaptarla; sus datos no se copian.
LoRA / QLoRA
Técnicas para ajustar un modelo con poco costo. En este proyecto no se usan todavía: son una fase condicional posterior.
